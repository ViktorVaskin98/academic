Пара мест, где слив уходит чуть дальше, чем карточки Яндекса:

| Слив | Что добавить |

| #9 | Бэггинг над линейными моделями — снова линейная модель, выигрыша почти нет |
| #10 | +10 000 деревьев: RF — плато, GBDT — переобучение |
| #12 | Почему на проде GBDT, а не RF: мелкие деревья быстрее; распараллеливание на одном объекте не спасает из-за overhead потоков |
| #13 | «Веса» для L1 / L2 в GBDT — значения в листьях: $w_j = -\frac{G_j}{H_j + \lambda}$. Подбор гиперпараметров: grid → random → байесовская оптимизация (optuna, TPE) |

**Байесовская оптимизация (дыра, нет нигде) — минимум для ответа.** Строим дешёвую
суррогатную модель «гиперпараметры → качество» по уже сделанным запускам и выбираем
следующую точку, максимизируя функцию приобретения (баланс «там, где хорошо» и «там, где
неопределённость велика»). Гауссовский процесс — классика; **TPE** (optuna, hyperopt) делит
запуски на хорошие и плохие по квантилю, моделирует плотности $l(x) = p(x \mid \text{хорошо})$ и
$g(x) = p(x \mid \text{плохо})$ и берёт $x$, максимизирующий $l(x)/g(x)$. Random search лучше grid,
когда важны немногие из многих параметров: grid тратит попытки на повторение одних и тех же
значений важного параметра.
