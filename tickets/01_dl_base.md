## А-1. MLP, активации, softmax и кросс-энтропия

**⏱ Триггер.** Полносвязный слой: $h = \sigma(Wx + b)$. Без нелинейности композиция слоёв —
снова линейная функция ($W_2 W_1 x = W' x$), глубина бесполезна. С нелинейностью MLP с одним
скрытым слоем — универсальный аппроксиматор (любую непрерывную функцию на компакте с любой
точностью), но ширина может понадобиться экспоненциальная. **Глубина** даёт ту же выразительность
куда меньшим числом параметров — композиция переиспользует признаки.

**🧩 Активации — что и почему.**

| Активация | Формула | Плюсы | Минусы |
|---|---|---|---|
| sigmoid | $\frac{1}{1+e^{-x}}$ | выход в $(0,1)$ — для вероятности на выходе | $\sigma' \le 1/4$ → затухание градиента; выход не центрирован |
| tanh | $\frac{e^x - e^{-x}}{e^x + e^{-x}}$ | центрирован | насыщается на краях, та же проблема |
| **ReLU** | $\max(0, x)$ | производная 1 на положительной части → градиент не затухает; дёшево; разреженность | **dying ReLU**: нейрон, ушедший в минус на всех объектах, больше не обновляется |
| Leaky ReLU / ELU | $\max(\alpha x, x)$ | чинит dying ReLU | ещё гиперпараметр |
| **GELU** | $x \cdot \Phi(x)$ | гладкая, стандарт в трансформерах (BERT, GPT) | дороже ReLU |
| SwiGLU | $\text{Swish}(xW) \odot xV$ | стандарт FFN в современных LLM (LLaMA) | +1 матрица |

**Выход и лосс.** Для $K$ классов: $p_k = \text{softmax}(z)_k = \frac{e^{z_k}}{\sum_j e^{z_j}}$,
лосс — кросс-энтропия $L = -\log p_y$. Градиент по логитам — ключевая формула:
$$\frac{\partial L}{\partial z_k} = p_k - [k = y]$$
«предсказанное минус истинное» — та же форма, что у логрега. Softmax для $K = 2$ сводится к сигмоиде
от разности логитов.

**Численная устойчивость.** $e^{z}$ переполняется при $z \sim 100$. Трюк: $\text{softmax}(z) = \text{softmax}(z - \max z)$.
Лосс считают сразу через log-sum-exp: $-\log p_y = -z_y + \log\sum_j e^{z_j}$ — поэтому в PyTorch
`CrossEntropyLoss` принимает **логиты**, а не вероятности. Для NLP это не мелочь: softmax идёт по словарю
в 30–150 тыс. токенов.

**⚠️ Ловушки.** Говорить «ReLU не имеет производной в нуле — это проблема» (на практике берут субградиент 0 или 1, не важно).
Путать softmax со многими независимыми сигмоидами: softmax — классы взаимоисключающие, сигмоиды — multilabel.
Подавать в `CrossEntropyLoss` уже посчитанный softmax — двойной softmax, обучение портится молча.

## А-2. Backprop и граф вычислений 🧮

**⏱ Триггер.** Backprop — это цепное правило, применённое к графу вычислений **от выхода к входу**
с переиспользованием промежуточных результатов. Прямой проход считает и запоминает активации,
обратный — градиенты: для каждого узла $\frac{\partial L}{\partial x} = \sum_{\text{дети } y}\frac{\partial L}{\partial y}\frac{\partial y}{\partial x}$.
Стоимость обратного прохода — того же порядка, что прямого (~2×).

**🧩 Почему именно reverse mode.** Функция $f: \mathbb{R}^n \to \mathbb{R}$ — много параметров, один скаляр-лосс.
Forward mode даёт производную по **одному входу** за проход → $n$ проходов. Reverse mode — градиент по **всем входам**
за один проход. Для нейросети с $10^8$ параметров это разница между «обучается» и «нет».

**🧩 Пример на доске: слой $y = Wx$.** Пусть пришёл $\delta = \frac{\partial L}{\partial y}$. Тогда
$$\frac{\partial L}{\partial W} = \delta\, x^\top, \qquad \frac{\partial L}{\partial x} = W^\top \delta.$$
Через ReLU: $\delta_{\text{до}} = \delta_{\text{после}} \odot [z > 0]$. Отсюда прямо видно, почему нужно хранить
активации прямого прохода — **память на обучении растёт с глубиной и размером батча** (мост к А-7).

**⚠️ Ловушки.** Говорить «backprop — это алгоритм оптимизации». Нет: backprop только **считает** градиент,
оптимизирует SGD / Adam. Путать градиент по весам (нужен для шага) и по входам (нужен, чтобы передать ошибку назад).

## А-3. Затухающие и взрывающиеся градиенты, инициализация

**⏱ Триггер.** Градиент по ранним слоям — произведение якобианов всех последующих:
$\frac{\partial L}{\partial h_1} = \frac{\partial L}{\partial h_T}\prod_{t}\frac{\partial h_{t+1}}{\partial h_t}$.
Если нормы множителей систематически $< 1$ — градиент затухает экспоненциально с глубиной (ранние слои не учатся),
если $> 1$ — взрывается (NaN, скачки лосса).

**🧩 Причины и лекарства.**

| Причина | Лекарство |
|---|---|
| Насыщающие активации: $\sigma' \le 1/4$, за 10 слоёв $\le 10^{-6}$ | ReLU / GELU |
| Плохой масштаб весов | Xavier / He инициализация |
| Длинные цепочки (глубина, RNN во времени) | residual-связи (А-10), LSTM (А-15) |
| Дрейф масштаба активаций при обучении | нормализация (А-4) |
| Взрыв | gradient clipping (А-6) |

**🧩 Инициализация — вывод на пальцах.** Для $y = \sum_{i=1}^{n_{in}} w_i x_i$ с независимыми нулевыми средними:
$\text{Var}(y) = n_{in}\,\text{Var}(w)\,\text{Var}(x)$. Хотим $\text{Var}(y) = \text{Var}(x)$ — дисперсия не должна
ни расти, ни падать от слоя к слою:
- **Xavier (Glorot):** $\text{Var}(w) = \frac{2}{n_{in} + n_{out}}$ — компромисс прямого и обратного прохода; для tanh / sigmoid.
- **He (Kaiming):** $\text{Var}(w) = \frac{2}{n_{in}}$ — ReLU обнуляет половину входов, поэтому двойка.

Нулевая инициализация — нельзя: все нейроны слоя получат одинаковый градиент и останутся одинаковыми (симметрия не разрушается).

**⚠️ Ловушки.** Считать, что ReLU полностью решил проблему — для глубины 50+ без residual и нормализации всё равно не учится.
Путать затухание градиента с переобучением.

## А-4. BatchNorm vs LayerNorm ⭐⚠️

**⏱ Триггер.** Оба нормализуют активации к нулевому среднему и единичной дисперсии, а затем
возвращают масштаб обучаемыми $\gamma, \beta$: $\hat x = \frac{x - \mu}{\sqrt{\sigma^2 + \varepsilon}}$, $y = \gamma\hat x + \beta$.
Разница — **по каким осям** считаются $\mu$ и $\sigma^2$.

| | BatchNorm | LayerNorm |
|---|---|---|
| Статистика | по **батчу**, для каждого признака / канала | по **признакам**, для каждого объекта / токена |
| Train vs inference | train — статистики батча; inference — **скользящие средние**, накопленные на обучении | одинаково всегда |
| Зависит от батча | да — ломается на маленьких батчах и при разной длине последовательностей | нет |
| Где | CNN | трансформеры, RNN |

Ещё два варианта из слива: **Instance Norm** — по пространству для каждого канала и объекта (перенос стиля),
**Group Norm** — по группам каналов для каждого объекта (детекция, маленькие батчи). **RMSNorm** — LayerNorm без вычитания
среднего, только деление на RMS; стандарт в LLaMA-подобных моделях, дешевле.

**🧩 Почему в трансформерах LayerNorm.** (1) Последовательности разной длины с паддингом — статистика по батчу
смешивает реальные токены с паддингом; (2) батчи маленькие, статистики шумные; (3) при авторегрессионной генерации
«батча» по сути нет; (4) нет расхождения между train и inference.

**🧩 Зачем вообще нормализация.** Исходная мотивация — «internal covariate shift» (распределение входов слоя меняется,
пока учатся предыдущие). Современное понимание — нормализация **сглаживает ландшафт лосса**, позволяет брать больший lr
и делает обучение менее чувствительным к инициализации. Регуляризующий эффект у BatchNorm есть, но **побочный**
(шум от статистик батча).

**⚠️ Ловушки.** ⚠️ Слив подаёт BatchNorm как основной способ регуляризации — лучше явно разделить «нормализация» и
«регуляризация». Забыть `model.eval()`: BatchNorm продолжит использовать статистики текущего батча, предсказания
будут зависеть от соседей по батчу. Говорить, что LayerNorm нормализует «по слою» в смысле по всем нейронам сети.

## А-5. Регуляризация нейросетей, dropout ⭐

**⏱ Триггер.** Способы: weight decay (L2 / AdamW), **dropout**, early stopping, аугментации данных, label smoothing,
stochastic depth, mixup. Dropout: на обучении каждый нейрон обнуляется с вероятностью $p$ независимо;
сеть не может полагаться на конкретный нейрон → учит избыточные, устойчивые признаки. Интерпретация — неявный
ансамбль из $2^n$ подсетей с общими весами.

**🧩 Dropout на инференсе — главный вопрос.** На обучении матожидание активации — $(1-p)\,h$. На инференсе нейроны не
выключаем, значит нужно согласовать масштаб. Два эквивалентных способа:
- **классический:** на инференсе умножить активации на $(1 - p)$;
- **inverted dropout (PyTorch, стандарт):** на обучении делить оставшиеся на $(1 - p)$, на инференсе dropout — тождество.

Inverted удобнее: инференс-код не знает про dropout вообще, достаточно `model.eval()`.

**🧩 Остальное коротко.**
- **Weight decay:** $w \leftarrow w - \eta\lambda w$ на каждом шаге. Для SGD эквивалентен L2 в лоссе, для Adam — **нет** (А-6).
- **Early stopping:** останавливаемся, когда валидационный лосс перестал падать; эквивалентен ограничению нормы весов
  (для линейной модели с GD — близко к L2).
- **Label smoothing:** цель $(1-\varepsilon)$ для верного класса и $\varepsilon/(K-1)$ для остальных — модель не уходит
  в бесконечно уверенные логиты, лучше калибровка.
- **Аугментации:** в CV — кропы, флипы, цвет; в NLP — back-translation, замена синонимов, случайное удаление слов — слабее,
  чем в CV, потому что смысл текста хрупкий.

**⚠️ Ловушки.** Сказать «на инференсе dropout выкидывает нейроны случайно» — нет, если не MC-dropout.
Путать $p$ как вероятность **выкинуть** и как вероятность **оставить** (в старом Keras / статьях бывает по-разному — проговорить).
Ставить dropout после BatchNorm бездумно — у них плохо сочетаются статистики.

## А-6. Оптимизаторы: momentum → Adam → AdamW, warmup, clipping ⭐

**⏱ Триггер.** Линия развития — каждый шаг чинит конкретную проблему предыдущего:

| Метод | Обновление | Что чинит |
|---|---|---|
| SGD | $w \leftarrow w - \eta g$ | — |
| Momentum (Поляк) | $v \leftarrow \beta v + g$, $w \leftarrow w - \eta v$ | зигзаги в вытянутых оврагах: поперечные компоненты гасятся, продольные копятся |
| Nesterov | градиент в точке «заглядывания» $w - \eta\beta v$ | меньше перелёт |
| Adagrad | $G \leftarrow G + g^2$, $w \leftarrow w - \frac{\eta}{\sqrt{G}+\varepsilon} g$ | свой шаг для каждого параметра: редкие признаки (эмбеддинги редких слов!) получают большие шаги |
| RMSProp | $G \leftarrow \rho G + (1-\rho) g^2$ | у Adagrad $G$ только растёт → шаг умирает; экспоненциальное среднее это чинит |
| **Adam** | momentum ($m$) + RMSProp ($v$) + **bias correction** $\hat m = \frac{m}{1-\beta_1^t}$, $\hat v = \frac{v}{1-\beta_2^t}$ | объединяет; поправка нужна, потому что $m, v$ стартуют с нуля и в начале занижены |
| **AdamW** | weight decay отдельно: $w \leftarrow w - \eta(\hat m / (\sqrt{\hat v}+\varepsilon) + \lambda w)$ | в Adam L2-штраф попадает в градиент и **делится на $\sqrt{\hat v}$** — параметры с большим градиентом регуляризуются слабее. AdamW применяет затухание к весам напрямую |

Дефолты: Adam $\beta_1 = 0.9$, $\beta_2 = 0.999$; для трансформеров — **AdamW**, $\lambda \approx 0.01$.

**🧩 Warmup и расписания.** Первые сотни–тысячи шагов lr линейно растёт от 0. Зачем: в начале оценки $v$ у Adam построены
по нескольким градиентам и ненадёжны, большой шаг даёт огромное случайное обновление; для трансформеров с post-LN без
warmup обучение просто расходится. Дальше — cosine или linear decay. Для fine-tuning BERT типично: lr $2\text{e-}5$…$5\text{e-}5$,
warmup 6–10% шагов, linear decay.

**🧩 Gradient clipping.** Если $\|g\| > c$, то $g \leftarrow c\,\frac{g}{\|g\|}$. Обрезается **норма всего вектора**, направление
сохраняется. Нужно в RNN и трансформерах, типично $c = 1$.

**⚠️ Ловушки.** ⚠️ Слив: «AdaGrad (RMSProp)» — **это два разных метода**, RMSProp — исправление Adagrad.
Приписывать momentum Нестерову (momentum — Поляк, у Нестерова — модификация; уже было в redo-list `ml_sobes`, Б-27).
Не назвать bias correction. Сказать, что AdamW — «Adam с L2» — это ровно то, чем он **не** является.

## А-7. Память и большие батчи: accumulation, bf16, checkpointing ⭐⚠️

**⏱ Триггер.** Задача из слива: хотим batch 2048, в память влезает 32. **Gradient accumulation:** на каждом микро-батче
считаем `loss / 64`, делаем `backward()` — градиенты суммируются в `.grad`; `optimizer.step()` и `zero_grad()` — раз в
$2048/32 = 64$ микро-батча. Эффективный батч 2048, память — как на 32.

**🧩 Три нюанса, которых нет в сливе — именно их ждут:**
1. **Loss делим на число шагов накопления.** Иначе градиент в 64 раза больше, чем у настоящего батча 2048, — фактически
   lr ×64.
2. **BatchNorm не эквивалентен.** Статистики считаются по 32 объектам, а не по 2048. В трансформерах LayerNorm — и там
   всё эквивалентно. Это стоит сказать явно — показывает понимание.
3. **Contrastive loss с in-batch negatives не эквивалентен.** При микро-батче 32 у каждого примера 31 негатив, а не 2047.
   Для SBERT / CLIP-подобного обучения нужны другие трюки (GradCache, memory bank, большой батч на нескольких GPU).

**🧩 Куда уходит память на обучении:** веса + градиенты + состояния оптимизатора (у Adam два тензора $m, v$ размером с веса)
+ **активации** (растут с батчем × длиной × глубиной). Для модели на $N$ параметров в fp32 с Adam — ~$16N$ байт до активаций.

| Приём | Что экономит | Цена |
|---|---|---|
| Mixed precision (**bf16** / fp16) | активации и вычисления ~×2 | fp16 требует loss scaling (переполнение / underflow градиентов), bf16 — нет: тот же диапазон, что у fp32 |
| **Gradient checkpointing** | активации: храним только часть, остальное пересчитываем на обратном проходе | +~30% времени |
| 8-bit оптимизаторы | состояния Adam | немного точности |
| ZeRO / FSDP | шардинг весов, градиентов, состояний по GPU | нужны несколько GPU |
| LoRA (А-35) | градиенты и состояния только для малых адаптеров | меньше гибкость |

**Как менять lr при росте батча.** Linear scaling rule: батч ×$k$ → lr ×$k$ (для SGD), обязательно с warmup;
для Adam чаще ×$\sqrt{k}$ или подбор заново.
