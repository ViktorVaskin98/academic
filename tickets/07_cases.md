## А-37. Модерация: контакты в тексте объявления ⭐

**⏱ Триггер — слив #4 и #7.** Продавцы оставляют телефон / мессенджер в описании, чтобы увести сделку с платформы
(обход монетизации и защиты сделки). Нужна модель + **две** зоны порогов:
- **автоотклонение** — порог по **precision**: ложное отклонение бьёт по честному пользователю, исправить некому →
  precision ≥ заданного уровня (например, 99%);
- **ручная модерация** — порог по **recall при ограничении по объёму**: модераторы исправят ложные срабатывания, поэтому
  ловим максимум, но в очередь уходит не больше, чем они успеют разобрать.
- ниже — пропускаем. Итого три зоны по скору.

**🧩 Модель — от простого к сложному.**
1. **Регулярки** на телефоны / ники / ссылки — высокий precision, низкий recall. Бейзлайн и признак.
2. **Обфускация** — главная трудность: «восемь девять два шесть…», «8 9 2 6», «т.е.л.е.г.р.а.м», латиница вместо кириллицы,
   цифры словами. Против неё — символьные n-граммы (А-12), BERT, нормализация текста.
3. **BERT-классификатор** «есть контакт / нет» (А-27) или **NER** — найти и **замаскировать** контакт, а не отклонять
   объявление целиком (А-32). Это продуктовое решение: мягче для пользователя.
4. Контакты на **фото** — OCR + тот же текстовый классификатор. Уточнить, в скоупе ли.

**🧩 Метрики — ловушка AUC (слив #7).** ROC-AUC > 0.99 и **ни одного** положительного в топ-1000, отправленных
модераторам, — возможно. Пример: 1k положительных, 999k отрицательных; по возрастанию скора: 990k отрицательных → 1k
положительных → 9k отрицательных. AUC $\approx 990/999 \approx 0.991$, а топ-1000 целиком отрицательный. ROC-AUC —
глобальная метрика ранжирования, при сильном дисбалансе её определяет масса лёгких негативов. **Мерить надо то, что
использует бизнес:** **precision@k**, где $k$ — ёмкость модерации; recall при фиксированном потоке; PR-AUC.

**🧩 Грабли разметки и прода.**
- **Selection bias:** метки есть только у того, что модель отправила модераторам. Новые типы обфускации модель никогда не
  отправит → никогда не узнаем. Лекарство — **случайная доля потока** в ручную разметку (exploration).
- **Adversarial drift:** нарушители адаптируются к модели за дни–недели → мониторинг доли срабатываний, регулярное
  переобучение, быстрые правила как заплатка.
- **Доля нарушителей меняется** → порог по precision, подобранный на валидации, «уплывает» — пересчитывать.
- **Latency:** модерация при публикации — сотни миллисекунд; дистилляция / квантование (А-27).

**⚠️ Ловушки.** Перепутать, где precision, а где recall. Отчитываться ROC-AUC. Не упомянуть обфускацию и адаптацию
нарушителей. Не спросить про ёмкость модераторов.

## А-38. Поиск дубликатов объявлений ⭐

**⏱ Триггер.** Продавец публикует одно и то же объявление много раз (или с нескольких аккаунтов), чтобы забить выдачу.
Задача — найти **пары / группы дубликатов** среди сотен миллионов объявлений. Попарно сравнивать всё со всем —
$O(N^2)$, невозможно. Классическая схема — **двухстадийная**:
1. **Генерация кандидатов (дёшево, высокий recall):** эмбеддинги текста (SBERT, А-30) и фото → ANN-поиск top-$k$ соседей
   (А-31); плюс блокировка по простым ключам — тот же телефон, категория, город; MinHash / LSH для почти-дословных копий.
2. **Классификатор пары (точно, высокий precision):** cross-encoder по текстам (А-31) или GBDT на признаках похожести:
   косинус текстов, косинус фото, совпадение цены / города / категории, общий телефон / устройство, разница во времени
   публикации.
3. **Группировка:** пары → граф → компоненты связности = группа дубликатов.

**🧩 Что считать дубликатом — уточнить первым.** Два объявления «iPhone 15 128GB» от **разных** продавцов — **не**
дубликаты, это конкуренты. Один и тот же товар от одного человека с двух аккаунтов — дубликат. Поэтому текстовой
похожести мало: нужны признаки продавца и фото (одинаковые фото — сильный сигнал), и **hard negatives** в обучении —
похожие объявления разных продавцов.

**🧩 Метрики и разметка.** Precision / recall на размеченных парах; для кандидатов — recall@k первой стадии (нельзя
найти то, что не попало в кандидаты). Разметка — модераторы, жалобы пользователей; активное обучение — размечать пары
около порога.

**⚠️ Ловушки.** Предлагать сравнивать всё со всем. Называть дубликатом любую семантическую близость. Не разделять
стадии и их метрики.

## А-39. Антифрод: классификация аккаунта по окружению ⭐

**⏱ Триггер — слив #26.** Недобросовестные продавцы плодят аккаунты. У аккаунта есть **окружение** — похожие по
технической информации (тот же IP, устройство, платёжные данные), их **произвольное число**, порядок не важен. Нужна
архитектура, классифицирующая аккаунт по окружению.

**Ключевое свойство:** вход — **множество** переменного размера → модель должна быть **инвариантна к перестановкам**.

**🧩 Варианты — по нарастанию.**
1. **Ручные агрегаты + GBDT** — бейзлайн: число соседей, доля забаненных соседей, распределение похожестей, средний
   возраст аккаунтов окружения. Всегда начинать с него.
2. **Deep Sets** (Zaheer et al., 2017): $f(X) = \rho\left(\sum_{x \in X}\phi(x)\right)$. $\phi$ — сеть, кодирующая каждого соседа,
   сумма (или mean / max) — **симметричная** операция, поэтому порядок не важен, а число элементов любое. Теорема:
   любую инвариантную к перестановкам функцию множества можно представить в таком виде.
3. **Attention без позиционных кодировок** (Set Transformer): self-attention эквивариантен к перестановкам (А-19) +
   пулинг → инвариантность. Плюс к Deep Sets — учитывает **взаимодействие соседей между собой** (десять соседей похожи и
   на аккаунт, и **друг на друга** — это ферма).
4. **GNN:** аккаунты — узлы, общие IP / устройства / контакты — рёбра. **GAT:** $\alpha_{ij} = \text{softmax}_j\left(\text{LeakyReLU}(a^\top[Wh_i \,\|\, Wh_j])\right)$ —
   attention по соседям взвешивает, какие связи важнее (общий IP в кафе — слабый сигнал, общее устройство — сильный).
   Естественно захватывает окружение второго и третьего порядка. **GraphSAGE** — сэмплирование соседей для графов на
   миллионы узлов.

**🧩 Альтернатива из слива.** Найти самого похожего соседа и учить сиамскую модель на паре. Слабое место: «много умеренно
похожих соседей» — ни один не похож сильно, но вместе это подозрительно. Поэтому нужен агрегат по **всему** окружению.

**🧩 Грабли.** **Утечка по графу:** признак «сосед забанен», если бан случился **после** момента предсказания — сплит по
времени. Разметка — баны модераторов (смещена в сторону уже пойманных схем). Связь с NLP: признаки узла — эмбеддинги
текстов объявлений аккаунта (А-30) — похожие тексты на разных аккаунтах тоже рёбра.

**⚠️ Ловушки.** Предложить RNN / обычный MLP на конкатенации — зависит от порядка и фиксирует размер. Не объяснить,
**почему** сумма даёт инвариантность. Пропустить бейзлайн на агрегатах.
