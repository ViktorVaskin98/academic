### Режим "надрочить" — дневная структура и spaced repetition
Цель — довести распознавание паттерна и написание кода до автоматизма, а не один раз прорешать и забыть.

**Формат дня (~2-2.5 ч, 5 дней в неделю):**
1. **Warm-up (10-15 мин)** — 1 задача, **холодная, без подсказок, с таймером**. Начиная со 2-й недели. С недели 3 слот чередуется: ~3 раза в неделю — **новая задача из Яндекс-трека по уже пройденной теме** (отмечены 🔄 в [`YANDEX_TRACK.md`](YANDEX_TRACK.md)), ~2 раза — холодный повтор из `redo-list.md`. Смысл: новая задача на знакомый паттерн тренирует распознавание лучше, чем повторное решение уже виденной, а слот при этом не растёт по времени.
2. **Основной блок (~1.5-2 ч)** — теория нового паттерна (15-20 мин) + 4-6 новых задач по теме недели (было 2-4, потом 3-5 — по итогам ретро недели 1 увеличили ещё, темп даётся легко, паттерны заходят с первого раза).
3. **Python internals:**
   - Новая тема (~20-30 мин) — **2 раза в неделю**, по `PYTHON_PLAN.md`.
   - **Quick-fire (~5 мин) — каждый день**, включая дни без новой темы: один вопрос-самопроверка из уже пройденных тем (по кругу, не новый материал). По итогам ретро недели 1 — Python-темы редко попадаются между собой (2 раза в неделю), это добавлено, чтобы material не забывался между сессиями, без раздувания программы.
4. **SQL (~20-30 мин, 2 раза в неделю)** — по [`SQL_PLAN.md`](SQL_PLAN.md), с нуля. Ставится в дни, свободные от Python-темы, чтобы день не перегружался. Формат — задачи в чате под сквозную схему, с сессии 3 частично на локальной SQLite.

**Список пересдач (`interview-prep/redo-list.md`):**
- Любая задача, которая заняла >20 минут, решена с подглядыванием в решение, или где ты не сразу увидел паттерн — уходит в `redo-list.md` с датой.
- Пересдача **холодная** (закрыть старое решение, начать с чистого листа): через 3 дня и через 7 дней после первого решения.
- Если пересдача снова не идёт с первого захода — задача остаётся в списке ещё на один цикл (3 дня), паттерн явно не закрыт.
- Не убирай задачу из списка, пока не решишь её холодно 2 раза подряд без сбоев.

## Неделя 3 — Prefix sums (ядро) + Binary Search
**Сложность: средняя** — это твоя проседающая тема (было на реальном собесе), поэтому объём задач по префиксам увеличен против остальных недель, и они возвращаются в warm-up на всех последующих неделях.
**Разгружено по итогам ретро дня 2 недели 2** (неделя была перегружена — 7 новых концепций против 2-3 в среднем): 2D prefix sum и difference array вынесены в бонус/резерв недели 8 — они реже спрашиваются на intern-скрининге (нишевые), убирать их совсем смысла нет, но тащить обязательными в и без того плотную неделю — тоже.

- Темы:
  - Базовый prefix sum 1D (`prefix[i] = prefix[i-1] + a[i]`), сумма на диапазоне за O(1)
  - Prefix sum + hashmap (запоминаем, на каком префиксе какая сумма/остаток встречалась) — ключевой паттерн для "subarray с суммой/условием", самая частая часть темы на собесах
  - Prefix XOR (тот же трюк, что и prefix sum, но с XOR — почти бесплатно после hashmap-варианта)
  - Явно проговорить связь: prefix sum — это "накопленное состояние слева", тот же принцип, что и running streak из недели 1, только с суммой вместо счётчика
- Задачи:
  - База: Range Sum Query — Immutable (303), Running Sum of 1d Array (1480)
  - Prefix + hashmap: Subarray Sum Equals K (560), Continuous Subarray Sum (523), Subarray Sums Divisible by K (974)
  - Prefix XOR: XOR Queries of a Subarray (1310)
  - Binary search: Binary Search (704), Search in Rotated Sorted Array (33), Find Minimum in Rotated Sorted Array (153), Koko Eating Bananas (875) — binary search on answer
- **Яндекс-трек (4 задачи):** М-1 «Подотрезок с суммой X» (= LC560, уже ядро недели), М-5 «Разделить массив на 3 подмассива мин. стоимости» (LC3010), ДУ-1 «K ближайших к a[index]» (LC658, за O(K)), ПС-1 «K ближайших к X» (LC658 через `lower_bound` — та же задача другим методом, полезно сравнить подходы)
- Python internals: итераторы и генераторы — протокол `__iter__`/`__next__`, `yield`, ленивые вычисления, `itertools` (accumulate — буквально prefix sum "из коробки", groupby, pairwise)

**Бонус/резерв (перенесено в неделю 8, делать только если останется время):** 2D prefix sum — Range Sum Query 2D — Immutable (304); difference array — Corporate Flight Bookings (1109), Car Pooling (1094)

## Что не входит и почему
- Продвинутые графовые алгоритмы (Dijkstra, MST, топологическая сортировка), сложный DP (2D, на деревьях), продвинутые структуры (Trie, DSU, Segment Tree) — по опыту редко спрашивают на intern-уровне за 45 минут; если после недели 8 останется время/понадобится под конкретную компанию — добавим отдельным блоком.
- **Базовый DP и обход графов урезаны до минимального пола** (2 и 1 задача соответственно) после разбора Яндекс-трека: в 39 реальных задачах с их алгосекций нет **ни одной** на DP и ни одной на обход графа. Полностью не убираем — это хедж на случай собесов в другие компании, где профиль может отличаться. Если решишь целиться строго в Яндекс — можно срезать и этот пол, освободится ~1.5 дня под строки.
