# План по Python internals (собеседования ML Engineer / Intern)

Синхронизирован с [`PLAN.md`](PLAN.md) — 8 недель, 2 темы в неделю (~20-30 мин на тему), по средам/пятницам или как удобно в твоём графике. Цель — не "прочитать", а уметь **объяснить своими словами + показать на маленьком примере кода**, потому что именно так это спрашивают на собесах ("что выведет этот код", "почему").

Формат каждой темы:
- **Изучить** — что читать/на чём фокус
- **Уметь объяснить** — контрольные вопросы, которые реально задают
- **Мини-практика** — написать руками маленький кусок кода, не копировать
- **Самопроверка** — вопрос-ловушка "что выведет"

## Неделя 1

### 1.1 Data model: mutable vs immutable, `is` vs `==`
- **Изучить:** какие типы mutable (list, dict, set) vs immutable (int, str, tuple, frozenset); `id()`, small int cache (-5..256) и string interning; всё в Python — объект
- **Уметь объяснить:** почему `a = 256; b = 256; a is b` → True, а `a = 257; b = 257; a is b` → не гарантировано True; почему tuple с mutable элементом внутри не полностью immutable
- **Мини-практика:** написать функцию, которая показывает разницу поведения при передаче list vs tuple в функцию с попыткой "изменить" аргумент
- **Самопроверка:** что выведет `a = [1,2]; b = a; b.append(3); print(a)`? А если `b = a.copy()`?

### 1.2 Big-O встроенных структур в CPython
- **Изучить:** сложности операций list (append amortized O(1), insert/pop(0) O(n), индексация O(1)), dict/set (avg O(1), worst O(n)), почему `x in list` — O(n), а `x in set` — O(1)
- **Уметь объяснить:** почему `list.pop(0)` плохо в цикле, чем `deque` лучше для этого
- **Мини-практика:** засечь время `x in list` vs `x in set` на 100k элементах (`timeit`)
- **Самопроверка:** что асимптотически быстрее — 1000 раз `list.append` или 1000 раз `list.insert(0, x)`?

## Неделя 6

### 6.1 GIL и модели параллелизма
- **Изучить:** что такое GIL и зачем он нужен (упрощает управление памятью/refcounting), почему threading не ускоряет CPU-bound задачи в CPython, но ускоряет I/O-bound; multiprocessing обходит GIL ценой отдельных процессов
- **Уметь объяснить:** в лоб — "почему Python threading медленный для вычислений", и когда threading всё-таки уместен
- **Мини-практика:** сравнить время CPU-bound задачи (например, суммирование в цикле) в 1 потоке vs 4 threading.Thread vs 4 multiprocessing.Process
- **Самопроверка:** ускорит ли threading скачивание 10 файлов по сети? А парсинг 10 больших JSON в памяти?

### 6.2 `async`/`await` и event loop
- **Изучить:** корутины, event loop, `asyncio.gather`, чем `async` отличается от threading (кооперативная многозадачность в одном потоке), когда `async` реально даёт выигрыш (I/O-bound, много одновременных ожиданий)
- **Уметь объяснить:** почему `await asyncio.sleep(1)` не блокирует другие корутины, а `time.sleep(1)` внутри `async def` — блокирует всё
- **Мини-практика:** написать 3 корутины с `asyncio.sleep` и запустить их через `asyncio.gather`, засечь, что суммарное время ≈ max, а не sum
- **Самопроверка:** что будет, если внутри `async def` вызвать обычную блокирующую функцию (например, `time.sleep`)?
