# Неделя 2 — Two Pointers + Hash Map

**Сложность: средняя**
**Режим:** 4-6 задач/день, warm-up каждый день (холодная задача из недели 1), Python quick-fire каждый день (5 мин)
**Новое с этой недели:** SQL с нуля — 2 сессии (дни 2 и 5), см. [`SQL_PLAN.md`](../SQL_PLAN.md)

Два самых частых паттерна на intern-скрининге. Главная цель недели — не просто решить, а **научиться отличать** "это two pointers" от "это hash map" по формулировке условия, до написания кода.

## Ключевая развилка недели (проговаривать перед каждой задачей)

| Признак в условии | Скорее всего паттерн |
|---|---|
| Массив **отсортирован** / можно отсортировать без потери смысла | two pointers (с двух концов) |
| Ищем **пару/тройку** с заданной суммой в отсортированном | two pointers |
| Нужны **исходные индексы**, сортировать нельзя | hash map |
| Вопрос про **частоты / дубликаты / группировку** | hash map (Counter/defaultdict) |
| Палиндром, разворот, "схлопывание" с двух сторон | two pointers |
| "Есть ли элемент X" за O(1) внутри цикла | hash map / set |
| Нужно O(1) доп. памяти, массив отсортирован | two pointers |

## День 1 — Two pointers: база (схлопывание с двух концов)

- [x] **Warm-up (холодно, 10 мин):** Maximum Subarray (53)
- [x] Теория: два указателя с концов (`left=0`, `right=n-1`), инвариант "ответ всегда внутри [left, right]", почему сдвигаем именно тот указатель, а не другой
- [x] Two Sum II — Input Array Is Sorted (167) — канонический two pointers

- [x] Squares of a Sorted Array (977) — two pointers навстречу, заполнение результата с конца
- [x] **Python quick-fire:** что выведет `a=[1,2]; b=a; b.append(3); print(a)` и почему?

**Что должно щёлкнуть к концу дня:** two pointers — это способ за O(n) обойти то, что наивно требует O(n²) вложенных циклов, за счёт **отсортированности** (или другого порядка), которая позволяет на каждом шаге гарантированно отбросить целую группу вариантов.

## День 4 — Hash map: сумма/индексы, множества как инструмент

- [x] **Warm-up (холодно, 10 мин):** Longest Strictly Increasing or Strictly Decreasing Subarray (3105)
- [x] Two Sum (1) — классика "нужны индексы → сортировать нельзя → hash map"
- [x] Longest Consecutive Sequence (128) — **самая интересная за неделю**: set + трюк "начинаю считать серию только с начала серии", даёт O(n) вместо O(n log n) — чисто с первого раза после наводки
- [x] Contains Duplicate II (219) — hash map "значение → последний индекс" — чисто
- [x] Intersection of Two Arrays (349) — операции над множествами, плюс показан альтернативный вариант sorted + two pointers (O(1) доп. памяти)
- [x] 🇾 **Яндекс-трек Х-3 «Пересечение топов двух выдач»** — прямое усиление LC349, за линию через два растущих hash-сета — сам поймал баг (`.add(i)` вместо `.add(nums1[i])`) и почти сам вывел алгоритм
- [x] 🇾 **Яндекс-трек Х-1 «Оптимизация маршрута»** 🖊 — авторская, тяжело зашла, решение дано целиком после нескольких заходов; не в `redo-list.md` (нечастый паттерн, не стоит холодной пересдачи)
- [x] ~~Python internals 2.2~~ — закрыто досрочно в день 3
- [ ] **Python quick-fire**

**Что должно щёлкнуть:** в Longest Consecutive Sequence — почему проверка `if num-1 not in num_set` превращает потенциально O(n²) в O(n). Это тот тип рассуждения (амортизация по всем сериям), который стоит уметь проговорить вслух.
